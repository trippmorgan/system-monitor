## Directory Purposes

**agents/**
- Purpose: Contains role definitions for specialized Claude agents
- Contains: CLAUDE.md files with agent instructions and capabilities
- Key files: `agents/system-tech/CLAUDE.md`, `agents/news-curator/CLAUDE.md`, `agents/orchestrator/CLAUDE.md`
- Access: Agents launched via `dispatch.sh` or direct `cd` + `claude` command

**dashboard/**
- Purpose: Web-based UI and real-time data collection
- Contains: HTML/CSS/JavaScript UI, shell scripts for fetching data, generated JSON caches
- Key files: `index.html`, `launch.sh`, `system-stats.sh`, `news-fetcher.sh`
- Runtime: Serves on http://localhost:8787; uses news-cache/ directory

**dashboard/news-cache/**
- Purpose: Runtime cache for dashboard data (auto-generated)
- Contains: JSON files with current metrics and news
- Key files: `stats.json`, `news.json`, `meta.json`
- Generated by: `system-stats.sh` and `news-fetcher.sh` (every 30s and 2min respectively)
- Consumed by: `index.html` via JavaScript fetch calls

**scripts/**
- Purpose: Standalone shell scripts for monitoring and maintenance
- Contains: Health checks, monitoring daemons, cleanup utilities
- Key files: `health-check.sh`, `system-monitor-assistant.sh`, `cleanup.sh`
- Usage: Run manually or via cron; some can run as background daemons

**logs/**
- Purpose: Persistent log storage
- Contains: Daily reports, alert history, state files
- Key files: `daily-report-*.log`, `alerts.log`, `.monitor-state.json`
- Lifecycle: alerts.log appends indefinitely; daily reports are per-date; .monitor-state.json is JSON state file
- Retention: Controlled by config.sh LOG_RETENTION_DAYS

**Root directory**
- `config.sh`: Master configuration file (sourced by all scripts)
- `dispatch.sh`: Entry point for agent dispatch menu
- `CLAUDE.md`: High-level project documentation for Claude
- `README.md`: User-facing documentation

## Key File Locations

**Entry Points:**

- `dashboard/launch.sh`: Starts the complete dashboard ecosystem
- `dispatch.sh`: Launches agent selection menu
- `scripts/health-check.sh`: Daily system health report
- `scripts/system-monitor-assistant.sh`: Continuous background monitor

**Configuration:**

- `config.sh`: All thresholds, paths, feature flags, service lists
- `agents/*/CLAUDE.md`: Agent-specific role and capability definitions
- `~/.config/system-monitor/config`: User overrides for configuration

**Core Logic:**

- `dashboard/system-stats.sh`: Metric collection (CPU, memory, disk, GPU, services)
- `dashboard/news-fetcher.sh`: News aggregation from 8 categories, bias scoring
- `scripts/system-monitor-assistant.sh`: Change-based alerting and thresholds
- `scripts/health-check.sh`: Comprehensive daily health report generation

**Testing & Validation:**

- `scripts/validate.sh`: Configuration validation script

**UI & Presentation:**

- `dashboard/index.html`: Main arcade-themed web dashboard
- `dashboard/dashboard.sh`: Terminal-based alternative dashboard

## Naming Conventions

**Files:**

- Shell scripts: `kebab-case.sh` (e.g., `system-stats.sh`, `news-fetcher.sh`)
- Configuration: `config.sh` or `CLAUDE.md` or `README.md`
- JSON output: `lowercase.json` (e.g., `stats.json`, `news.json`)
- Log files: `type-YYYY-MM-DD.log` (e.g., `daily-report-2026-02-08.log`)
- Hidden state files: `.dotfile-name` (e.g., `.monitor-state.json`, `.refresh.pid`)

**Directories:**

- Agent directories: `kebab-case/` (e.g., `system-tech/`, `news-curator/`)
- Data directories: `lowercase/` (e.g., `news-cache/`, `logs/`)
- Functional directories: `functional-name/` (e.g., `dashboard/`, `scripts/`, `agents/`)

**Variables in scripts:**

- Configuration: UPPERCASE_WITH_UNDERSCORES (e.g., `CPU_WARN`, `DASHBOARD_PORT`)
- Local: lowercase_with_underscores (e.g., `script_dir`, `stats_file`)
- Constants: UPPERCASE_WITH_UNDERSCORES (e.g., `HAS_JQ`, `ENABLE_GPU_MONITORING`)

**JSON field names:**

- camelCase for nested objects (e.g., `cpu.load`, `memory.percent`, `gpu.temp`)
- snake_case for multi-word top-level keys when necessary (e.g., `bias_label`)

## Where to Add New Code

**New System Metric:**

1. Collection: Add extraction to `dashboard/system-stats.sh` (around line 44-90)
2. JSON output: Add field to the JSON block at end of `system-stats.sh` (lines 96-135)
3. Display: Add progress bar or label to `dashboard/index.html` (LEFT COLUMN section, ~line 269-295)
4. Alerting: Add threshold check to `scripts/system-monitor-assistant.sh` if needed
5. Thresholds: Add config variables to `config.sh` (lines 19-46)

**New News Category:**

1. Fetching: Add fetch logic to `dashboard/news-fetcher.sh` (after line 100)
2. Data model: Ensure item includes `category` field matching category name
3. Display: Add `<div>` section to `dashboard/index.html` grid (around line 326-339)
4. JavaScript: Add to `categories` object in `loadArcadeData()` function (line 438)
5. Configuration: Optional: add NEWS_CATEGORY_ENABLED flag to `config.sh`

**New Threshold Alert:**

1. Configuration: Add threshold variables to `config.sh` (lines 19-46)
2. Collection: Ensure metric collected in `dashboard/system-stats.sh`
3. Monitoring: Add comparison logic to `scripts/system-monitor-assistant.sh` (after line 100)
4. Logging: Use `log_alert()` function to write to `$ALERT_LOG`

**New Script or Tool:**

- Location: `scripts/` for standalone utilities, `dashboard/` if part of dashboard
- Pattern: Include shebang (`#!/bin/bash`), load config.sh, document with comment header
- Naming: `kebab-case-name.sh`
- Make executable: `chmod +x scripts/your-script.sh`

**New Agent:**

1. Create directory: `agents/your-agent-name/`
2. Create `CLAUDE.md` with role definition (see `agents/system-tech/CLAUDE.md` as template)
3. Update `dispatch.sh` to add menu option pointing to new agent
4. Define what data/scripts the agent can access vs. is blocked from

**Dashboard Component:**

- All UI is in `dashboard/index.html` (HTML, CSS, and JavaScript)
- Add HTML sections to appropriate grid column (left, center, right)
- Add fetch/render logic to JavaScript section (lines 362-520)
- Use NES.css classes: `.nes-container`, `.nes-btn`, `.nes-input`, `.nes-progress`

## Special Directories

**news-cache/** (Dashboard runtime data)
- Purpose: Transient cache of stats and news for dashboard consumption
- Generated: Yes (clobbered every 30-120 seconds)
- Committed: No (in .gitignore)
- Structure: JSON files with live system metrics and aggregated news
- Lifecycle: Created by launch.sh; populated by background refresh loop

**logs/** (Persistent logs)
- Purpose: Audit trail and troubleshooting
- Generated: Yes (appended and created as needed)
- Committed: No (in .gitignore)
- Retention: Controlled by LOG_RETENTION_DAYS in config.sh
- Key files: alerts.log (shared append), daily-report-*.log (per-date), .monitor-state.json (JSON state)

**.claude-team/** (Claude team metadata)
- Purpose: Internal metadata for Claude Code operations
- Generated: Yes (by Claude)
- Committed: No (in .gitignore)
- Contents: Not part of application logic

**agents/** (Agent definitions)
- Purpose: Specialized Claude agent role definitions
- Generated: No (hand-written)
- Committed: Yes
- Each agent has CLAUDE.md defining capabilities and restrictions
